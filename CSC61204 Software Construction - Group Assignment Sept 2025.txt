1.0 Assignment Overview
The assignment will be handed out in Week 5 and is due in Week 13 on Friday, 19 December
2025. It carries a weight of 30% of the final grade and must be completed in groups of 4 to 5
students.
This group assignment requires you to apply the principles of software construction to design,
develop, test, and deliver a complete software application. Working in a team, you will select a
real-world scenario aligned with the United Nations Sustainable Development Goal 4 (Quality
Education).
The project is divided into two phases, each with specific deliverables, to guide you through the
software construction lifecycle. You will be assessed on your ability to apply technical skills in OO
design, implementation, and testing, as well as your capacity for effective teamwork,
communication, and reflection.

2.0 Learning Outcomes
This assignment assesses students’ ability to apply software construction techniques through
collaborative teamwork (MLO2, C4, 30%) and to demonstrate lifelong learning through selfdirected reflection and skill development (TGC4).

Your final submission must be a single compressed file (.zip or .rar) containing the following
items:
1. Final Executable Code: A runnable file (e.g., .jar, .exe) of your completed application.
2. Source Code: The complete project source code, including all libraries and dependencies.
3. Comprehensive Technical Report: A single document (.docx or .pdf) that follows the
structure outlined in the Final Report Outline. This report must include:
● The completed Cover Page.
● All required UML diagrams, reports, and reflections (more details in Required
Templates file).
● Turnitin Report: Maximum similarity allowed is 30%, and AI detection score must
be 30% or below.

8.0 Report Outline
The report should follow a structured approach; each section requires specific content as
summarized below.
8.1 Executive Summary (0.5–1 page)
Briefly describe your project — the problem, your Object-Oriented solution (e.g., “Java-based

Testing System using Strategy Pattern”), main outcomes (e.g., API integration, high test
coverage), and how it supports SDG 4: Quality Education.
8.2 Chapter 1: Introduction (1–2 pages)
• Background: Context and relevance to SDG 4.
• Motivation: Why this problem matters.
• Real-world Problem: The issue your software solves.
• Objectives: Key goals of the project.
• Outcomes: Expected benefits or impact.
8.3 Chapter 2: Literature Review (2–3 pages)
Summarize key studies, technologies, and market insights related to your topic. Cite all sources
in APA style.
8.4 Chapter 3: Design & Modelling (3–5 pages)
• Architecture: Explain system components and interactions.
• UML Diagram: Show Inheritance and Polymorphism.
• Design Pattern: Name and justify the chosen pattern (e.g., Strategy Pattern) and how it
improves maintainability.
8.5 Chapter 4: Construction & Unit Testing (3–4 pages)
• Core Logic: Describe main classes and logic.
• Testing: Mention the framework (e.g., JUnit) and code coverage %.
• Examples: Include 2–3 test cases (at least one failed case).
Attach the full test report in Appendix A.
8.6 Chapter 5: Integration & Application (3–5 pages)
• GUI: Add screenshots and explain design choices.
• API Integration: Describe the API and error handling.
• System Testing: Provide a table of at least 5 test cases (end-to-end tests).
8.7 Chapter 6: Conclusion & Professional Practice (2–3 pages)
• Video Link: Insert your demo video (60–90 seconds).
• Reflection:
1. How it supports SDG 4.
2. Scalability potential.
3. Teamwork roles, challenge, and solution.
8.8 References (1–2 pages)
List all cited sources in APA format.
8.9 Appendices (Optional)
Include supporting materials:
• A: Full code or Git link.
• B: Full Unit Test Report.
• C: Installation/Execution Guide.
